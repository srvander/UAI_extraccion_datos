01 · ¿Qué es web scraping?

Volver a etapas ↑

Es la obtención automatizada de información publicada en una web para convertirla en datos reutilizables: filas, campos, archivos o enlaces. Un scraper realiza solicitudes, interpreta respuestas y guarda resultados.

Automatización web

Reproduce acciones de una persona en una interfaz: abrir, hacer clic, completar y descargar. Playwright, visto en la sesión 01, sirve cuando la interacción del navegador importa.

Web scraping

Se centra en extraer y estructurar información. Puede usar un navegador, pero si el servidor entrega HTML o JSON directamente, una solicitud HTTP suele bastar.

Ejemplo: pulsar «siguiente» en una revista es automatización; reunir título, autor, DOI y enlace de cada artículo en un CSV es scraping. Un proyecto puede combinar ambas técnicas.

Riesgos de uso

  • Disponibilidad: muchas solicitudes simultáneas pueden degradar el servicio.
  • Acceso: autenticación, barreras técnicas y permisos delimitan qué puede consultarse.
  • Datos personales: que una página sea visible no autoriza cualquier tratamiento posterior, especialmente el masivo.
  • Reutilización: revisar licencias, condiciones del sitio y derechos sobre obras y bases de datos.
  • Calidad: cambios de estructura, paginación y duplicados alteran resultados silenciosamente.

02 · Riesgos penales: Ley N° 21.459

Volver a etapas ↑

La técnica de extracción, por sí sola, no determina el delito. Hay que comprobar la conducta, el medio exigido por el tipo y los hechos del caso. Leemos los artículos 1 y 2 en Ley Chile.

NormaElementos relevantesPregunta para un scraper
Art. 2 · Acceso ilícito El que, sin autorización o excediendo la autorización que posea y superando barreras técnicas o medidas tecnológicas de seguridad, acceda a un sistema informático¿Hubo una barrera técnica real que el programa superó? Una URL pública y la mera automatización no satisfacen por sí solas ese requisito.
Art. 1 · Integridad del sistemaEl que obstaculice o impida el normal funcionamiento, total o parcial, de un sistema informático, a través de la introducción, transmisión, daño, deterioro, alteración o supresión de los datos informáticos¿Se probó una afectación del funcionamiento y el mecanismo típico? Una carga excesiva o un DoS puede plantear este análisis, pero el volumen de peticiones no basta por sí solo.
Distinción clave: páginas accesibles al público, condiciones de uso, límites de tasa y barreras técnicas son hechos distintos. El incumplimiento de una condición contractual no equivale automáticamente al artículo 2; tampoco toda ralentización configura el artículo 1.

Decisiones antes de ejecutar

  1. Confirmar que el contenido y la ruta son públicos y que no se eluden controles.
  2. Leer condiciones de uso, licencia y robots.txt; evaluar también reglas especiales según la fuente.
  3. Limitar páginas, frecuencia y descargas; detenerse ante 403, 429 o fallos repetidos.
  4. Minimizar datos personales y documentar propósito, origen y fecha de extracción.

Para datos personales del sistema de tramitación electrónica del Poder Judicial existe además una regla específica: el artículo 2 letra c de la Ley N° 20.886 prohíbe su tratamiento masivo sin autorización previa.

03 · Jurisprudencia para discutir

Volver a etapas ↑

Chile · 2026

In-House Company SpA / CAPJ

La Corte de Apelaciones de Valparaíso rechazó un amparo económico frente a la negativa de autorizar uso masivo automatizado de datos judiciales. Aplicó la regla especial de la Ley N° 20.886 y consideró la protección de datos y el riesgo de colapso del servicio. La Corte Suprema confirmó el 29 de julio de 2026.

Alcance: resuelve una acción constitucional sobre autorización de tratamiento masivo; no declara cometido un delito de la Ley N° 21.459 ni prohíbe todo scraping.

C.A. Valparaíso, rol 1494-2026 ↗Corte Suprema, rol 38.680-2026 ↗

Estados Unidos · 2022

hiQ Labs v. LinkedIn

El Noveno Circuito volvió a confirmar una medida cautelar en un litigio por extracción de perfiles públicos. Estimó que había preguntas serias sobre si ese acceso podía ser «sin autorización» bajo la CFAA estadounidense.

Alcance: decisión cautelar y derecho extranjero; no interpreta la Ley N° 21.459. Sirve para comparar contenido público y espacios con control de acceso.

04 · HTTPX: solicitudes con Python

Volver a etapas ↑

HTTPX ofrece una misma interfaz para HTML, JSON y descargas; clientes síncronos y asíncronos; límites de tiempo; y reutilización de conexiones mediante Client. Eso permite enseñar primero el flujo HTTP sencillo y ampliar después a servicios dinámicos. Para clics, JavaScript o estados complejos, sigue siendo útil Playwright.

python -m pip install httpx
import httpx

url = "https://rchdt.uchile.cl/index.php/RCHDT/issue/current"
with httpx.Client(timeout=10, follow_redirects=True) as client:
    respuesta = client.get(url)
    respuesta.raise_for_status()
    print(respuesta.status_code, respuesta.url)
    print(respuesta.text[:300])

raise_for_status() detecta errores HTTP; follow_redirects=True es explícito porque HTTPX no sigue redirecciones por defecto; Client reutiliza conexiones. Consulta la documentación de clientes y la guía básica.

05 · APIs visibles e internas

Volver a etapas ↑

Una API es una interfaz para pedir datos u operaciones a un sistema. En la web, la interfaz puede solicitar al servidor un documento HTML, un archivo o una respuesta JSON. «API interna» u «oculta» suele nombrar una ruta que usa la propia página sin documentación pública; que aparezca en la pestaña Red no implica permiso para usarla libremente.

Navegador→Solicitud HTTP→JSON o archivo→Interfaz

Cómo reconocer la fuente de datos

  1. Abre herramientas de desarrollador → Red / Network, filtra por Fetch/XHR y recarga.
  2. Activa un filtro de la página. Observa URL, método, parámetros, encabezados, estado y respuesta.
  3. Si la respuesta es JSON, identifica la lista y sus campos. Si es un documento, comprueba tipo MIME, tamaño y URL final.
  4. Reproduce solo solicitudes públicas permitidas, con parámetros necesarios y una frecuencia moderada. Evita copiar cookies, tokens o credenciales a scripts compartidos.

En páginas dinámicas el HTML inicial puede contener solo un contenedor vacío; los datos aparecen tras una solicitud posterior. Para un JSON público, el patrón básico es:

import httpx

with httpx.Client(timeout=10) as client:
    r = client.get("https://sitio.example/api/articulos", params={"pagina": 1})
    r.raise_for_status()
    datos = r.json()
    for articulo in datos["resultados"]:
        print(articulo["titulo"])

La URL anterior es un esquema didáctico, no un servicio real. Para practicar sin depender de un portal ajeno, abre el laboratorio de API local y observa su solicitud JSON en Red.

06 · Caso: Revista Chilena de Derecho y Tecnología

Volver a etapas ↑

Usamos la revista de la Universidad de Chile. Su número actual muestra enlaces a fichas de artículos; cada ficha entrega metadatos y acceso a PDF. La revista declara acceso libre a sus contenidos. Este caso combina scraping HTML y descarga documental sin asumir que exista una API pública estable.

Objetivo del scraper

Crear un CSV con título, autores, DOI, URL del artículo y URL del PDF para un máximo de tres artículos. La descarga de un PDF es opcional. El script consulta secuencialmente, espera entre solicitudes y se detiene ante errores.
